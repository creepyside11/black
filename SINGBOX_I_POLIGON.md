# Sing-box и тестовый полигон Lua

Инструкция для сборки `black_lua_loader.zip`. Все команды `/...` вводятся в консоли программы после `python bot.py`, остальные — в Termux.

## 1. Установка sing-box один раз

В Termux:

```sh
pkg update
pkg install sing-box -y
sing-box version
```

Это установка программы sing-box. Самих VPN-подписок и настроек узла в сборке нет: используйте свою подписку или свой конфиг. Не публикуйте ссылки подписок, конфиги и ключи.

## 2. Как работает автоматический запуск

В программе есть два независимых способа работы с sing-box:

1. **Узлы `/vpn`.** После добавления и проверки подписки программа запускает для нужных поддерживаемых узлов отдельные локальные мосты по необходимости. При старте программы пул сохранённых подписок также выполняет фоновую проверку. Бинарник sing-box должен быть установлен.
2. **Своя конфигурация `_sb/config.json`.** Если такой файл существует, программа при запуске `python bot.py` проверит его и попробует запустить отдельный sing-box. Файл не создаётся автоматически из воздуха. Это не означает, что выбранные из него прокси автоматически назначены аккаунтам.

Если файла `_sb/config.json` нет и вы используете только `/vpn`, отдельный конфигурационный процесс не нужен. Статус этого процесса может быть «не запущен» при работающих мостах `/vpn` — это разные процессы.

Перед стартом процесса конфигурации программа выполняет `sing-box check`. Она не устанавливает sing-box и не скачивает подписку без вашей команды.

## 3. Работа с подпиской через консоль

После запуска программы и перехода в консоль:

```text
/vpn add <ссылка_на_вашу_подписку>
/vpn ping
/vpn
/vpn use <имя_узла> 1
```

Замените `1` на ID аккаунта, а имя — на имя из списка. Некоторые типы узлов могут быть неподдерживаемыми или не пройти проверку TCP/UDP. Ошибка или занятый порт будут отражены в выводе. Автоматический запуск локального процесса сам по себе не гарантирует, что внешний сервер доступен или UDP проходит.

Вывод `/vpn` может содержать адреса и другие сведения о подписке. Удаляйте личные данные перед отправкой логов другим людям.

## 4. Собственный конфиг sing-box

Создайте или положите свой совместимый конфиг в каталог установки:

```text
_sb/config.json
```

Если он лежит в другом месте, укажите путь в Termux до запуска программы:

```sh
export BR_SINGBOX_CONFIG="$HOME/my-singbox.json"
python bot.py
```

В консоли программы:

```text
/singbox status
/singbox start
/singbox stop
```

`status` показывает только процесс своего конфига `_sb/config.json`, а не все мосты `/vpn`.
`start` не запускает второй экземпляр, если управляемый программой процесс уже жив.
`stop` останавливает только тот процесс собственного конфига, который запустила эта программа. Мосты `/vpn` эта команда не останавливает.

Если конфиг не проходит проверку, выполните в Termux:

```sh
sing-box check -c _sb/config.json
```

Путь замените на свой, если файл расположен иначе. Если после этого конфиг проходит проверку, а процесс завершается, проверьте порты и попробуйте вручную `sing-box run -c _sb/config.json`, чтобы увидеть сообщение об ошибке. Не публикуйте полные сообщения без проверки на ключи и адреса.

Если команда сообщает «бинарник не найден», установите пакет и запустите `/singbox start` ещё раз. Для `/vpn` достаточно повторить `/vpn ping`; поиск установленного бинарника выполняется повторно. Для нестандартного пути можно задать переменную `SING_BOX_BIN` до запуска.

## 5. Тестовый полигон: отдельная папка

Тестовые сценарии хранятся в `test_lua_scripts/` в корне проекта. Рабочие сценарии по-прежнему хранятся в `scripts/lua/`. Файлы из тестовой папки не добавляются автоматически в список `/lua list` и не запускаются как рабочие.

В архиве есть `test_lua_scripts/example.lua` и `example_events.json`.
В консоли программы:

```text
/luatest list
/luatest run example.lua example_events.json
```

Команды полигона не создают аккаунт и не подключают его к игре. Скрипт получает вымышленные события, а вызовы вроде `br.walk`, `br.chat`, `br.send_json` и `br.route_save` отображаются как **имитация и не исполняются**. Отложенные `br.after` проверяются с виртуальным временем, без реального ожидания. События генерируются только из выбранного файла и таймеров скрипта.

Можно запустить тест и напрямую, не открывая `bot.py`:

```sh
cd "$HOME/black-routes/black-lua-loader"
python -m logic.lua_sandbox example.lua --events example_events.json
```

Загрузчику нужен Lua 5.4 (`pkg install lua54`). При необходимости укажите `BR_LUA_BIN`.

## 6. Как добавить свой тест

Допустим, `my_test.lua` находится в загрузках телефона. В Termux:

```sh
cd "$HOME/black-routes/black-lua-loader"
cp "$HOME/storage/downloads/my_test.lua" test_lua_scripts/my_test.lua
python -m logic.lua_sandbox my_test.lua --events example_events.json
```

Чтобы скопировать уже имеющийся рабочий Lua на проверку:

```sh
cp scripts/lua/my_bot.lua test_lua_scripts/my_bot.lua
python -m logic.lua_sandbox my_bot.lua --events example_events.json
```

Редактирование тестовой копии не меняет рабочий файл. Если вы захотите использовать проверенную копию для аккаунта, сначала проверьте содержание, затем отдельно скопируйте её в `scripts/lua/`.

## 7. Свой набор игровых событий

Создайте в `test_lua_scripts/` файл `my_events.json`. Пример:

```json
{
  "events": [
    {"at": 0, "name": "on_spawn", "args": {}},
    {"at": 1, "name": "on_chat", "args": {"message": "Тестовое сообщение"}},
    {"at": 3, "name": "on_json", "args": {"interface_id": 31, "data": {"o": 1}}}
  ]
}
```

`at` — виртуальное время в секундах от начала теста; `name` — имя события; `args` — его поля. Значения в примере учебные. Затем:

```text
/luatest run my_test.lua my_events.json
```

Без файла событий вызовется `on_load` и последующие запланированные таймеры. Для ограничения зависаний полигон обрабатывает максимум 200 событий, а обработчики Lua имеют таймаут движка.

## 8. Чего полигон пока не проверяет

Он не моделирует игровой сервер, авторизацию, реальное перемещение, доступность маршрута, награду и правильность неизвестных интерфейсов. Он не подтверждает успешное решение капчи. `on_action_result` для игровых действий сообщает `skipped`, а не `sent`; это имитация.

Позиция и данные аккаунта в тестовом снимке отсутствуют, `br.connected()` возвращает false, режим — `sandbox`. Если скрипту нужно протестировать другую ситуацию, её пока нужно выразить через события или расширить полигон. Если скрипт защищает действия условием `br.armed`, в полигоне ветка реального запуска может не выполняться.

Тесты в текущей среде использовали настоящий движок Lua 5.4 и имитацию sing-box/локального порта; настоящий sing-box, ваш Termux, игровая сессия и VPN-узел здесь не проверялись.
