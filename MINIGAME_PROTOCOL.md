# Мини-игры Black Russia — интерфейс 31

Снято с байткода `GUIMiniGameEventsGame` и четырёх его лейаутов
(classes4.dex, пакет `com.blackhub.bronline.game.gui.minigameevents`).
Таблица экранов `createGuiFromId` декодирована по сырым байтам: там
`packed-switch`, на котором обычный дизассемблер сбивается.

---

## 0. Этот документ НЕ про сбор урожая

Интерфейс 31 — это мини-игры событий (приз, развязывание, полоса,
картинка). Сбор яблок на ферме к ним не относится: в захвате
`_diag/apples.pcap` за всю мини-игру **нет ни одного интерфейса**, она
идёт целиком через RPC 437 с телом `0x0800 + слот`. Подробности —
в `HARVEST_PROTOCOL.md`, §0.

Раньше в `HARVEST_PROTOCOL.md` было написано, что сбор — это 31.
Это была ошибка, теперь исправлено.

## 1. Короткая версия

```
экран  : JSON интерфейс 31
режим  : ключ "g"  (0 приз / 1 развязывание / 2 полоса / 3 картинка)
ответ  : {"s": 1} попадание   {"s": 0} промах
         {"t": 1} время вышло {"c": 1} закрыть
```

**Автопрохождение — это `session.send_json(31, {"s": 1})`.**
Почему это работает, а не только «должно» — в §4.

---

## 2. Как клиент выбирает режим

`GUIMiniGameEventsGame.show(json)` создаёт `UIContainer` и добавляет в него
четыре лейаута по индексу:

| `g` | Лейаут | Что это |
|-----|--------|---------|
| 0 | `UILayoutMiniGameEventsGamePrize` | экран приза |
| 1 | `UILayoutMiniGameEventsGameUnTie` | развязывание |
| 2 | `UILayoutMiniGameEventsGameFinger` | полоса, бегущая линия |
| 3 | `UILayoutMiniGameEventsGameImage` | картинка |

Порядок `addLayout(индекс, лейаут)` в байткоде: `0`, `1`, `2`, `3`.
Сразу после этого `show()` читает `g` (`optInt`) и `x` (`optInt`).

---

## 3. Ответы — кто и когда шлёт

| Ключи | Метод | Условие |
|-------|-------|---------|
| `{"s": 1}` | `UILayoutMiniGameEventsGameFinger$RunVerticalLineView.lambda$onCreateView$0` | `isHitted() == true` |
| `{"s": 0}` | тот же метод | `isHitted() == false` |
| `{"t": 1}` | `UILayoutMiniGameEventsGameUnTie.lambda$onProgressEnd$2` | полоса прогресса дошла до конца |
| `{"c": 1}` | `GUIMiniGameEventsGame.onCreateView` | закрытие экрана |

Отправка всегда одна и та же:

```java
mGUIManager.sendJsonData(getGuiId(), json);   // getGuiId() == 31
```

После `{"s":1}` и `{"s":0}` клиент сразу зовёт `close(null)` — окно исчезает.

---

## 4. Почему автопрохождение вообще возможно

Это ключевой момент, и он в `RunVerticalLineView.isHitted()`:

```
iget v0, .x                      // позиция бегущей линии
get mChunk                       // целевая зона
cmpl-float / if-ltz
iget v0, .x
get mChunk
get mLineWidth
...                              // сравнение x с mChunk и mLineWidth
```

Ни одного обращения к серверу. Ни одного поля из входящего JSON.
**Попадание целиком вычисляется на клиенте из локальной геометрии анимации.**
Клиент сам решает «попал» и сам сообщает результат серверу.

Отсюда: чтобы пройти не играя, достаточно послать `{"s": 1}`.
Серверу нечем это опровергнуть — единственный источник вердикта это клиент.

Ограничение, которое я не могу проверить статикой: сервер может смотреть на
время между открытием экрана и ответом. Поэтому в коде стоит пауза
`HIT_DELAY = (0.8, 2.2)` секунды, а не мгновенный ответ.

## 6. Коллизия по id 31 — разобрана

Два класса заявляют `screenId = 31`:

- `GUIMiniGameEventsGame` — `getGuiId()` возвращает 31;
- `MiniGamesHelperWithJSON` — `iput v2, .screenId` с `const/16 #31`;
- `MiniGamesHelperGuiFragment` — передаёт 31 в `BaseISAMPGUIFragmentCompose`.

Это не двойное назначение, а два поколения одной механики. Проверка, кто живой:

1. `GUIManager.createGuiFromId(31)` → `GUIMiniGameEventsGame.newInstance()`.
   Декодировано по сырым байтам, ветка `if-eq v2, v0 -> 61`, инструкция 61.
2. `screensIsFragment` содержит 55 id, **31 в нём нет** — значит фрагментный
   путь для 31 не срабатывает, и `createGuiFromId` действительно вызывается.
3. `MiniGamesHelperWithJSON` создаётся только из
   `NetworkModule.provideMiniGamesHelperActionWithJSON` — то есть через Dagger,
   и ни один вызов не идёт из `createGuiFromId`.

Вывод: **в этой сборке живой экран 31 — `GUIMiniGameEventsGame`.**
`MiniGamesHelper*` — рефакторинг на Compose/ViewModel, не подключённый к
диспетчеру экранов.

Ключи и набор ответов у обоих совпадают (`g`, `s`, `t`, `c`), так что даже если
в следующей версии включат новый — наш обработчик продолжит работать.

Встроено так же, как капча: на каждый JSON проверяется id, для 31 запускается
фоновый поток (пауза перед ответом не должна блокировать обработчик пакетов).

```python
from logic.minigames import handle_minigame
handle_minigame(bot, interface_id, json_data)   # True, если это была мини-игра
```

### Дедупликация

Ключ — `(режим, p_title, x)`. Один экран = один ответ. Без этого повторный
пакет с тем же содержимым получал бы второй `{"s":1}`, что похоже на попытку
смошенничать и может быть замечено.

## 8. Про «Кресты дяди Славы»

В клиенте игры **этого названия нет.** Проверено по всем 5149 записям APK —
`Слав` в UTF-8 и UTF-16LE даёт 0 вхождений, `крест` даёт 4, и все четыре это
`перекресток` и «нажмите на крестик (Х)» в описаниях дорожных знаков.

В Photon оно **есть** — но только после расшифровки `.rodata`
(см. `_apk/photon_analysis.md` §2):

```
0x1ada91  " дяди Сла"
0x1ae7f0  "Дядя Сла"
0x1b3000  "Прохожде"
```

Плюс протокольные ключи `quest_id`, `quest_rejected`,
`questretry_after_ms` и команда `/quest`. То есть Photon работает с
квестами на уровне JSON, а не патчем памяти — тот же слой, что у нас.

Имя НПС приходит с сервера в поле `n` интерфейса 63, текст квеста — в `mq`
интерфейса 39. Поэтому искать механику по названию бессмысленно: его нет в
бинарнике by design.

Что есть точно: интерфейс 31 — единственный протокол мини-игр в клиенте, и
`Finger` (полоса с бегущей линией) — ровно тот тип механики, который боты
называют «крестами». Совпадение это или нет, покажет один прогон.

## 9. Что осталось проверить на живой игре

1. Приходит ли «кресты» как iid 31 с `g = 2`, или это другой экран.
2. Принимает ли сервер `{"s":1}` без реального прохождения. Пауза в коде
   есть, но проверка времени на сервере не исключена.
3. Что делает `g = 1` (развязывание) — сейчас на него уходит `{"c":1}`,
   потому что врать про таймаут рискованнее, чем закрыть.

`[ТРЕЙС] iid=... <json>` на каждый входящий JSON.
