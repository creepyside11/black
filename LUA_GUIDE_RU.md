# Lua-загрузчик для black

Версия: 1.0. Python 3.10+, Lua 5.4, Android/Termux или Linux. Проект работает как сетевой клиент; он не запускает графический экран Black Russia и не является Lua-загрузчиком внутри APK.

> Расширение API с таймерами, хранилищем, диалогами и примерами: [Lua API v2](docs/LUA_API_V2_RU.md). Старые функции сохраняются.

## 1. Два режима

**addon** — дополнение для конкретного аккаунта. Оно работает рядом с обычными задачами `black`. Загрузить можно до или после входа, но addon не запускает аккаунт сам. Если основной бот тоже управляет тем же действием, возможен конфликт.

**bot** — самостоятельный сценарий. Команда запускает Lua до подключения аккаунта, затем инициирует вход. Автоматический выбор спавна и стандартные обработчики капчи/мини-игр отключаются для этого аккаунта на время сценария. Стандартное подключение, регистрация/авторизация и сетевые механизмы проекта остаются в Python. Сам сценарий должен обработать меню спавна, мини-игру и т. д. Если Lua остановлен, автоматический выбор спавна не запускается задним числом.

В обоих режимах скрипт изолирован от скриптов других аккаунтов. Для одного аккаунта одновременно можно запустить один Lua-файл. Скрипты разных аккаунтов работают параллельно.

## 2. Установка на Android

Скачайте `black_lua_loader.zip` в Downloads. В Termux:

```sh
pkg update
pkg install python lua54 unzip -y
termux-setup-storage
mkdir -p "$HOME/black-lua"
unzip -o "$HOME/storage/downloads/black_lua_loader.zip" -d "$HOME/black-lua"
cd "$HOME/black-lua/black-lua-loader"
python bot.py
```

Архив содержит самостоятельную копию проекта. Существующие аккаунты не включены. При самом первом запуске программа открывает меню: нажмите `0`, чтобы перейти в консоль команд. Чтобы добавить свой аккаунт, в консоли программы введите `/add СЕРВЕР НИК ПАРОЛЬ`, затем `/list`. Пароль вводите локально. Синтаксис Lua при необходимости редактируйте любым текстовым редактором, например `nano scripts/lua/my_bot.lua` (`pkg install nano`).

Если Lua не найден, проверьте `lua5.4 -v`, `lua54 -v` или `lua -v`. Можно указать интерпретатор через переменную `BR_LUA_BIN`, например `export BR_LUA_BIN="$PREFIX/bin/lua5.4"`. Сборка проверена с Lua 5.4.8. Интерпретатор ставится отдельно: в архиве нет бинарника для телефона.

Для локального распознавания капчи дополнительно потребуются Pillow и Tesseract, например `pkg install tesseract` и `python -m pip install pillow`. Способ установки Pillow зависит от версии Termux. OCR не гарантирует правильного ответа. Внешний OCR по умолчанию не используется; если указать свой `RAKOCR_KEY`, проект может отправлять изображение стороннему сервису, заданному `RAKOCR_URL` или настройкой проекта.

## 3. Команды в консоли программы

```text
/lua help
/lua list
/lua addon 1 hello_addon.lua
/lua addon 1 minigame_example.lua --own-ui
/lua addon 1 hello_addon.lua --dry
/lua bot 1 spawn_bot.lua
/lua bot 1 spawn_bot.lua --dry
/lua status 1
/lua reload 1
/lua stop 1
```

`1` — ID из `/list`. Файлы должны находиться в `scripts/lua` или её подпапках. Путь с пробелами берите в кавычки. `--dry` записывает действия в лог и не выполняет изменяющие состояние команды. Неизвестные параметры приводят к ошибке: например, `--dru` не запустит скрипт с действиями по ошибке. `--packets` дополнительно включает частые события сырых пакетов. `--own-ui` передаёт скрипту ответственность за капчу и мини-игры: стандартные обработчики этих интерфейсов и сюжетные помощники не обрабатывают JSON для данного аккаунта. Эта опция автоматически включается в режиме bot. Обработчики самой активной основной задачи при этом продолжают работать: при конфликте остановите её командой `/task stop ID`. Конфигурация автоматического закрытия заставок выбирается при создании сессии: если addon подключён после входа, существующая настройка заставок сохраняется.

### Запуск дополнения

Добавьте аккаунт или используйте существующий. Если нужно, включите основную задачу обычной командой, например `/task mine 1`, и затем `/lua addon 1 hello_addon.lua`. При необходимости `/lua addon` можно вызвать до `/start 1`. Остановить дополнение: `/lua stop 1`; аккаунт останется подключённым.

### Запуск самостоятельного бота до спавна

Остановите аккаунт обычной командой `/stop 1`. Затем `/lua bot 1 spawn_bot.lua`. Загрузчик проверит скрипт, включит управление спавном через Lua и начнёт подключение аккаунта. Пример ожидает меню и выбирает первый ID из списка сервера. При другом протоколе нужно адаптировать скрипт. `/lua stop 1` останавливает Lua, а `/stop 1` останавливает аккаунт целиком. `reload` в режиме bot возможен только до соединения; если соединение активно, остановите аккаунт и запустите заново.

`/lua status 1` выводит состояние, счётчики и количество пропущенных событий. При частых сырых пакетах очередь может переполниться: такие события отбрасываются и учитываются в `queue_dropped`.

## 4. Жизненный цикл и события

Файл выполняется один раз, затем вызываются функции-обработчики. Можно определить `function on_json(e) ... end`, а также зарегистрировать функцию `br.event('имя', function(e) ... end)`. В отсутствие конкретного обработчика вызывается `on_event(e)`, если определён. Поле `e.name` содержит имя события.

| Событие | Поля e | Когда приходит |
|---|---|---|
| `on_load` | `armed`, `script` | После загрузки файла; API аккаунта ещё может отсутствовать |
| `on_tick` | `name` | Примерно каждые 0,25 секунды |
| `on_auth` | `state` | Стадия регистрации/авторизации проекта |
| `on_connect` | `name` | Событие подключения, которое выдаёт клиент проекта |
| `on_spawn_menu` | `data` | Меню доступных точек спавна |
| `on_spawn` | `name` | Событие клиента о спавне; само по себе не доказывает появление в мире |
| `on_disconnect` | `name` | Разрыв соединения |
| `on_json` | `interface_id`, `data` | JSON-интерфейс сервера |
| `on_rpc` | `rpc_id`, `payload_hex`, `size` | Входящий RPC |
| `on_packet` | `packet_id`, `body_hex`, `size` | Входящий пакет, только с `--packets` |
| `on_dialog` | `id`, `style`, `title`, `text`, `button1`, `button2` | Обычное окно диалога |
| `on_chat` | `message` | Сообщение чата |
| `on_map_icon` | `id`, `position`, `marker_type`, `style` | Сервер создал значок на карте |
| `on_map_icon_remove` | `id` | Сервер удалил значок |
| `on_npc_dialog` | `npc`, `text`, `model`, `buttons` | Окно NPC |
| `on_notification` | `text`, `button`, `has_button` | Уведомление |
| `on_checkpoint` | `x`, `y`, `z`, `radius` | Сервер создал метку |
| `on_checkpoint_clear` | `name` | Сервер удалил метку |
| `on_textdraw` | `id`, `data` | Показ элемента TextDraw |
| `on_textdraw_text` | `id`, `text` | Изменение текста TextDraw |
| `on_textdraw_hide` | `id` | Скрытие TextDraw |
| `on_move_end` | `movement`, `status` | Контроллер движения завершил или отменил перемещение |
| `on_action_result` | `source`, `results` | Результаты действий после обработки события |

Пакеты и строки для Lua ограничены по размеру: до 2048 байт содержимого пакета, до 4000 символов строки, до 64 элементов массива/объекта и глубины 6. Обрезанный hex имеет текстовый суффикс; его нельзя отправлять обратно как hex. `size` содержит размер исходного содержимого. Не записывайте в лог приватные данные сессии.

## 5. Чтение состояния

Данные — снимок на начало события; они могут измениться после него.

| Lua | Результат |
|---|---|
| `br.pos()` | `{x=..., y=..., z=...}` или `nil` |
| `br.now()` | Монотонное время в секундах, для интервалов; не часы телефона |
| `br.connected()` | Есть ли подключение сессии |
| `br.bot_id()` | Числовой ID аккаунта в программе |
| `br.mode()` | `addon` или `bot` |
| `br.vehicle_id()` | ID транспорта, если доступен |
| `br.health()`, `br.money()`, `br.interior()` | Число или `nil` |
| `br.server_tail(n)` | Последние строки, если источник подключён; по умолчанию пустой |
| `br.armed` | `true`, если изменяющие действия включены |
| `br.log(text)`, `print(...)` | Запись в лог бота |

Lua доступен с `math`, `string`, `table`, `utf8`, `coroutine` и стандартными безопасными примитивами. Доступ к `io`, `os`, `package`, `require`, `debug`, `dofile` и `load` скрипту не предоставляется. Это ограниченная среда исполнения, а не гарантия безопасности недоверенного кода.

## 6. Действия

Функции ниже ставят действия в список. Они возвращают успех постановки в список, а не подтверждение сервера. Python исполняет список после возврата обработчика. Действия из `on_load` выполняются в рабочем потоке, чтобы задержка не блокировала консоль. При остановке Lua следующие действия из очереди не выполняются. Результаты действий обработчиков событий доступны в `on_action_result` (действия из `on_load` пока не формируют это событие); `sent` означает, что вызов API выполнен, а не что сервер подтвердил результат. После `/lua ... --dry` команды, меняющие состояние, не отправляются.

| Команда | Действие |
|---|---|
| `br.walk(x,y,z)` | Запустить пешее движение к координатам |
| `br.drive(x,y,z)` | Запустить движение на транспорте |
| `br.tp(x,y,z)` | Использовать существующий в проекте способ перемещения |
| `br.keys(keys,lr,ud)` | Установить кнопки и оси; `br.keys(0)` отпускает |
| `br.vehicle(id,seat)` | Запросить посадку; `br.vehicle(0)` — выход |
| `br.stop_movement()` | Остановить текущее движение |
| `br.immortality(enabled)` | Включить или выключить имеющуюся в проекте защиту от голода; сервер может её не принять |
| `br.chat(text)` | Чат или команда, начинающаяся с `/` |
| `br.spawn_select(id)` | Выбрать ID из полученного меню спавна |
| `br.dialog(id,response,item,text)` | Ответить на обычный диалог |
| `br.npc(button)` | Ответ JSON-интерфейсу NPC 63 с профилем доставки NPC |
| `br.pickup(id)` | Взаимодействовать с пикапом; без ID — пикап с земли |
| `br.interact(id)` | RPC 436 с 32-битным ID |
| `br.select_textdraw(id)` | RPC 437 с 16-битным ID |
| `br.send_json(iid, table, packet_name)` | Отправить JSON в интерфейс; третий аргумент необязателен и задаёт существующий профиль `interface_*` проекта |
| `br.send_rpc(id, hex)` | Отправить RPC и тело в hex; ID 0..511 |
| `br.send_packet(id, hex)` | Отправить пакет и тело в hex; ID 0..255 |
| `br.solve_captcha(data)` | Запустить встроенный решатель по данным входящего интерфейса 26 |
| `br.after(seconds, event, data)` | Запланировать событие; задержка от 0 до 3600 секунд |
| `br.array(table)` | Явно обозначить Lua-таблицу как JSON-массив, например `br.array()` для `[]` |
| `br.null` | Значение JSON `null`; сравнивайте полученное значение с `br.null` |
| `br.sleep(seconds)` | Задержать очередь этого сценария; новые события ждут. Для большинства задач лучше `br.after` |
| `br.emit(table)` | Передать поддерживаемое мостом действие вручную |

При передаче входящего JSON пустые массивы и `null` сохраняются. Обычная пустая Lua-таблица `{}` сериализуется как объект `{}`; для пустого массива используйте `br.array()`. Значение `null` в данных события доступно как `br.null`; поля снимка `br.pos()`, `br.health()` и другие при отсутствии данных возвращают обычный Lua `nil`.

Ограничение — 32 действия за один вызов и 256 ожидающих таймеров. Лишние действия отбрасываются и отражаются в статусе. Один Lua-процесс и один последовательный обработчик работают на скрипт: долгие вызовы не останавливают другие аккаунты, но задерживают очередь этого скрипта. При зависании обработчика процесс прерывается по таймауту, ошибка попадает в лог.

Встроенные `br.u16(n)` и `br.u32(n)` создают hex-представление чисел little-endian. Например, `br.send_rpc(437, br.u16(2052))` эквивалентен `br.select_textdraw(2052)`. Дополнительные форматы можно собирать средствами Lua 5.4 (`string.pack`) и преобразовывать байты в hex. Сначала нужно знать реальный протокол конкретного сервера. Защита `br.immortality(true)` остаётся включённой после остановки скрипта; отключите её вызовом `br.immortality(false)` до остановки, если она больше не нужна.

## 7. Таймеры и случайные задержки

```lua
function on_load(e)
  local delay = math.random(20, 50) / 10
  br.after(delay, 'on_first_step', {message='готово'})
end

function on_first_step(e)
  br.log(e.message)
  br.walk(100.0, 200.0, 15.0)
end

function on_move_end(e)
  br.log('Завершилось движение: ' .. tostring(e.status))
end
```

Имена пользовательских обработчиков удобно начинать с `on_`, иначе их нужно зарегистрировать через `br.event`. Задержка не блокирует получение сетевых событий. `math.random` получает случайное начальное значение при каждой загрузке.

## 8. Пример своего интерфейса и мини-игры

```lua
function on_json(e)
  if e.interface_id == 123 and e.data and e.data.o == 1 then
    br.after(1.5, 'on_answer_custom', {})
  end
end
function on_answer_custom(e)
  br.send_json(123, {action='example'})
end
```

`123` и `{action='example'}` — учебный пример, а не готовый протокол игры. Замените их данными, которые вы реально установили по документации или записи. Точно так же можно реагировать на `on_rpc`, `on_packet`, диалоги, метки и TextDraw и отправлять RPC/пакеты. Неизвестную мини-игру загрузчик не расшифровывает автоматически. Функция открытия карты на экране APK относится к графическому клиенту; у сетевого бота экрана нет. Если карта управляется серверным интерфейсом, нужны его реальные сообщения.

Готовые примеры: `hello_addon.lua`, `spawn_bot.lua`, `minigame_example.lua`. Пример шахтного ползунка построен по конкретной записи и не гарантирует совместимость с другими версиями/мини-играми. В режиме addon с этим примером используйте `--own-ui`, иначе стандартный обработчик может отвечать на ту же мини-игру.

## 9. Капча

В режиме bot стандартная автоматическая обработка UI выключена. Чтобы запросить обработку капчи встроенным OCR, добавьте:

```lua
function on_json(e)
  if e.interface_id == 26 and e.data and e.data.o == 1 then
    br.solve_captcha(e.data)
  end
end
```

Решатель работает в фоне. Если окно капчи уже закрыто, сессия сменилась или скрипт остановлен, запоздалый результат Lua-решателя не отправляется. Отправка запроса не равна успешному прохождению: ожидайте закрытия окна и следующего подтверждённого состояния сервера. Если OCR не распознал изображение, проверьте лог. В addon без `--own-ui` встроенный обработчик уже активен, поэтому второй `br.solve_captcha` может дать дублирующий ответ.

## 10. Проверка и ограничения

Начинайте с `/lua addon 1 hello_addon.lua --dry`, проверяйте `/lua status 1` и логи. Затем тестируйте изменяющие действия на одном аккаунте. Ошибки синтаксиса показываются при загрузке; бесконечные циклы — как таймаут. Для примеров в архиве есть автоматические тесты, запускаемые командой `python -m unittest test_lua_integration` при установленном Lua.

Загрузчик не проверен на действующем игровом сервере. Подключение, спавн, конкретные действия, OCR, задержки и поведение модификаций необходимо отдельно проверять. Чужим Lua-скриптам и данным PCAP доверяйте только после проверки; не включайте в них пароли или токены.

## Настройки Lua-скриптов через Mini App

Панель VPS может сохранять индивидуальный набор настроек для каждого файла `.lua`. Укажите в панели JSON-объект, например:

```json
{
  "enabled": true,
  "timeout": 30,
  "delay": 1.5,
  "collect_harvest": true,
  "маршрут": {"название": "ферма", "точки": [1, 2, 3]}
}
```

Значения могут быть строками, числами, логическими `true`/`false`, списками и вложенными объектами. Названия параметров задаёт автор скрипта, в том числе на русском языке. Общий размер настроек — до 16 КиБ, вложенность — до 6 уровней. Скрипт сам решает, что означают параметры: панель не может автоматически добавить настройки в старый скрипт или изменить его поведение без соответствующего Lua-кода.

В коде используйте `br.setting(ключ, значение_по_умолчанию)`:

```lua
function on_load()
  local enabled = br.setting('enabled', true)
  local delay = br.setting('delay', 1.5)
  local timeout = br.setting('timeout', 30)
  if not enabled then
    br.log('Функция отключена в настройках')
    return
  end
  br.log('Задержка: ' .. tostring(delay) .. ', тайм-аут: ' .. tostring(timeout))
end
```

`br.settings()` возвращает таблицу всех значений для этого скрипта. Настройки передаются при запуске и обновляются в новых обработчиках событий. Если снять в панели галочку «Настройки скрипта включены», сохранённые значения останутся на VPS, но скрипт получит пустую таблицу и `br.setting` вернёт указанные в коде значения по умолчанию. Это не останавливает скрипт: чтобы выключить отдельную функцию, добавьте для неё логический параметр и проверку в Lua. Не храните секреты в этих настройках; API Token для автокапчи вводится в отдельном разделе панели и не передаётся в `br.settings()`.

Для работы этого интерфейса на VPS должна быть установлена версия загрузчика, содержащая `logic/lua_settings.py`. Панель сообщает, если этот модуль отсутствует.
