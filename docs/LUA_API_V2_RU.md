# Lua API RakCRMP: расширение v2

Этот документ дополняет [основное руководство](../LUA_GUIDE_RU.md). Новые функции работают в загрузчике RakCRMP, а не в произвольном Lua-интерпретаторе или Android APK. Существующие `br.version`, события, `br.after` и режимы `addon`/`bot` сохранены. Число `br.api_version` равно `2` в этой версии.

## Прежде чем запускать

- `addon` работает рядом с основной задачей. При конфликте действий их нужно согласовать.
- `bot` подключается до входа и отвечает за предусмотренные им игровые интерфейсы и выбор спавна.
- Загрузка скрипта не гарантирует прохождение игровой механики. Формат событий и подтверждения зависят от конкретного сервера.
- `--dry` не отправляет изменяющие игровые команды и не записывает постоянное хранилище. В тестовом полигоне действия имитируются.
- В функции-обработчике `br.*` для действий возвращает результат **постановки**, а не подтверждение сервером. Результат исполнения приходит позже в `on_action_result`.
- Для реального аккаунта нужен Lua 5.4 и установленная программа. При необходимости смотрите `LUA_GUIDE_RU.md`.
- Скрипт исполняется в ограниченном окружении. Это не обещание безопасности неизвестного кода: используйте доверенные Lua-файлы.

## Что добавлено

| Группа | Функции |
|---|---|
| Информация | `br.api_version`, `br.account()`, `br.last_dialog()`, `br.checkpoint()` |
| Таймеры | `br.timer_start()`, `br.timer_cancel()` |
| Текст и диалоги | `br.strip_colors()`, `br.lower()`, `br.contains()`, `br.dialog_rows()`, `br.find_dialog_row()` |
| Геометрия | `br.distance()`, `br.distance2d()`, `br.in_radius()` |
| Данные | `br.hex_encode()`, `br.hex_decode()`, `br.json_encode()`, `br.json_decode()` |
| Действия | `br.command()`, `br.request()` с меткой результата |
| Хранилище | `br.storage_get()`, `br.storage_all()`, `br.storage_set()`, `br.storage_delete()`, `br.storage_clear()` |

Информация — снимок на начало обработчика. События и вызовы упорядочены внутри одного Lua-сценария, но другие сценарии и сам сервер работают независимо. Данные могут устареть.

## Состояние аккаунта

```lua
function on_spawn(e)
  local account = br.account()
  if not account then
    br.log('Информация об аккаунте недоступна')
    return
  end
  br.log('Ник: ' .. tostring(account.nickname or '?'))
  br.log('Сервер: ' .. tostring(account.server or '?'))
  br.log('Статус: ' .. tostring(account.status or '?'))
  br.log('Последний уровень: ' .. tostring(account.level or '?'))
end
```

`br.account()` возвращает таблицу с `nickname`, `server`, `status`, `level`, `target_level`, либо `nil`, если снимок недоступен. Эти значения программа знает локально; `level` может быть старым. Пароль и токены сюда не добавляются. `br.bot_id()` по-прежнему возвращает локальный ID, который может измениться после перезапуска.

### Последний диалог

`br.last_dialog()` возвращает последний **полученный** `on_dialog`: `id`, `style`, `title`, `text`, `button1`, `button2`. Это история наблюдения, а не доказательство, что диалог ещё открыт. После подключения или разрыва она очищается.

```lua
function on_dialog(e)
  local last = br.last_dialog()
  if last and last.id == e.id then
    br.log('Получен диалог: ' .. tostring(last.title))
  end
end
```

### Метка

`br.checkpoint()` возвращает последнее наблюдённое `{x,y,z,radius}` или `nil`, если метка ещё не пришла, её убрали или соединение сбросилось.

```lua
function on_checkpoint(e)
  local target = br.checkpoint()
  local here = br.pos()
  local distance = br.distance(here, target)
  if distance then br.log(('До метки %.1f м'):format(distance)) end
end
```

Клиент видит только сообщения, которые действительно получил. Не предполагайте, что метка видна серверу или что путь к ней свободен.

## Таймеры

`br.after(seconds, event, data)` остаётся доступным и ведёт себя как прежде. Новый именованный таймер можно заменить или отменить по ID:

```lua
br.timer_start(id, seconds, event, data, interval)
br.timer_cancel(id)
```

- `id` — строка от 1 до 64 байт; одинаковый ID заменяет прежний таймер этого сценария.
- `seconds` — время первого срабатывания от 0 до 3600 секунд.
- `event` — имя `on_*`, до 100 байт; если не задано, используется `on_timer`.
- `data` — JSON-совместимые данные, доступные в `e.data`.
- `interval` — `0` или отсутствие для одноразового таймера; от `0.05` до `3600` для повторного.
- Событие содержит `e.timer_id`, `e.count` (с единицы), `e.data`.
- `timer_cancel` не прерывает уже исполняющийся обработчик. Отмена применяется после его возврата.
- Очередь общая с `br.after`; действует предел 256 таймеров на сценарий. Таймеры живут только пока работает сценарий, после перезапуска их нужно создать заново.
- Повтор планируется после выполнения предыдущего обработчика. Это не точный метроном: задержки сети и занятость процесса влияют на время.
- Возврат `true` означает, что действие попало в очередь Lua. При достижении лимита планировщика действительная ошибка будет в `on_action_result` и логе.

```lua
function on_load()
  br.timer_start('health', 3, 'on_health_timer', {min=30}, 10)
end

function on_health_timer(e)
  local hp = br.health()
  if hp and hp < e.data.min then
    br.log('Здоровье ниже порога')
  end
  if e.count >= 6 then
    br.timer_cancel(e.timer_id)
    br.log('Завершили периодическую проверку')
  end
end
```

`br.sleep()` останавливает обработку следующих событий этого сценария. Для ожидания диалога, движения или капчи лучше использовать событие и таймер с ограничением времени.

## Диалоги и строки

`br.strip_colors(text)` удаляет теги вида `{FFFFFF}`. `br.lower(text)` приводит к нижнему регистру латинские и русские буквы, включая Ё; это не полноценное преобразование регистра всех языков Unicode. `br.contains(text, needle, ignore_case)` ищет буквальную подстроку без Lua-паттернов.

`br.dialog_rows(text, style)` возвращает массив строк `{index, text, raw}`. `index` — нулевой индекс `list_item` для `br.dialog`. У стиля 5 первая непустая строка считается заголовком. Для других стилей заголовок не пропускается. Цветовые теги и нумерация в начале строки убираются из `text`, но сохраняются в `raw`.

`br.find_dialog_row(text, needle, style, ignore_case)` возвращает `index, text` первой найденной строки либо `nil`. Это только разбор текста: совпадение не подтверждает правильность ожидаемого меню.

```lua
function on_dialog(e)
  if not br.contains(br.strip_colors(e.title or ''), 'Меню игрока', true) then return end
  local item = br.find_dialog_row(e.text, 'Статистика', e.style, true)
  if item ~= nil then
    br.dialog(e.id, 1, item, '')
  else
    br.log('Пункт статистики не найден')
  end
end
```

Встроенный обработчик программы тоже может отвечать на диалоги. Если два обработчика одновременно управляют одним меню, возможен конфликт; проверяйте сценарий в нужном режиме.

## Расстояния

```lua
local distance3d = br.distance({x=0,y=0,z=0}, {x=3,y=4,z=12}) -- 13
local distance2d = br.distance2d({x=0,y=0}, {x=3,y=4})           -- 5
local near = br.in_radius(br.pos(), {x=1,y=2,z=3}, 10)
```

`distance` и `distance2d` возвращают `nil`, если нужных координат нет. `in_radius` возвращает `false`, если координаты или радиус недоступны. Единицы координат проекта обычно используются как метры, но точность зависит от протокола и источника координат. Эти функции не запускают движение и не строят маршрут.

## Hex и JSON

```lua
local hex = br.hex_encode('A')       -- '41'
local bytes = br.hex_decode('4100') -- 'A' + нулевой байт
local text, err = br.json_encode({step=2, items=br.array()})
local object, err2 = br.json_decode('{"step":2}')
```

- `hex_encode`: строка до 2048 байт; `hex_decode`: чётная hex-строка до 4096 символов. При ошибке — `nil`.
- `json_encode`/`json_decode`: до 16 КиБ. При ошибке — `nil, причина`. Ввод с лишними символами после JSON отклоняется.
- `br.array()` обозначает пустой массив, `{}` — пустой объект, `br.null` — JSON null. Значения данных событий и снимков могут обрезаться ограничениями моста; это не универсальная библиотека для больших JSON.
- Бинарные данные в обычные события и JSON напрямую передавать нельзя; применяйте hex и проверяйте пределы.

## Команды и метки действий

`br.command('/mm')` проверяет, что передана строка, начинающаяся с `/`, длиной не более 255 байт, и ставит обычное действие чата. Сервер может его отклонить. Для обычных сообщений используйте `br.chat`.

`br.request(action, tag)` ставит уже поддерживаемое действие с меткой 1–64 байта. Это низкоуровневая функция: `action.kind` и поля должны соответствовать существующему действию. Она **не** создаёт новые серверные RPC и не обходит `--dry`.

```lua
function on_chat(e)
  br.request({kind='chat', text='/mm'}, 'ask-stats')
end

function on_action_result(e)
  for _, result in ipairs(e.results or {}) do
    if result.tag == 'ask-stats' then
      br.log('Отправка команды: ' .. tostring(result.status))
    end
  end
end
```

`status='sent'` означает, что локальный мост принял и выполнил API-вызов, а не что сервер подтвердил изменение. `skipped` — холостой режим, `error` — ошибка. Действия из `on_load` сейчас не формируют `on_action_result`; не используйте метку как замену событию сервера. Не печатайте в лог пароли и токены.

## Постоянное хранилище

Хранилище позволяет запомнить этап или счётчик между запусками. Оно отдельно для комбинации проекта, сервера, ника и **полного пути файла сценария**. Если переместить проект, переименовать Lua-файл или аккаунт, старое хранилище автоматически не перенесётся. Данные лежат на машине в `lua_data/`, этот каталог исключён из Git. Файлы создаются с правами `0600` на поддерживаемых системах. Это не шифрование: не храните в них пароли и API-ключи.

| Вызов | Результат |
|---|---|
| `br.storage_get(key, default)` | Значение из снимка или `default`, если ключа нет |
| `br.storage_all()` | Поверхностная копия снимка либо `nil`, если хранилище недоступно |
| `br.storage_set(key, value)` | Поставить запись значения |
| `br.storage_delete(key)` | Поставить удаление ключа |
| `br.storage_clear()` | Поставить удаление всех ключей **только этого аккаунта и файла** |

Ключ — строка 1–64 байта. Значение — JSON-совместимое; Lua `nil` не записывается, для JSON null используйте `br.null`. Лимит — 64 ключа и 32 КиБ на файл, глубина до 6, до 64 элементов в объекте/массиве, строки до 4000 символов. При ошибке действие получает `status='error'`; повреждённый файл не заменяется автоматически. Запись атомарная на уровне файла. Снимок не обновляется внутри того же вызова: результат увидите в следующем событии, после выполнения действия. `--dry` не записывает файл.

```lua
function on_load()
  br.log('Последний этап: ' .. tostring(br.storage_get('stage', 0)))
end

function on_checkpoint(e)
  br.storage_set('stage', 1)
  br.after(0.5, 'on_check_stage', {})
end

function on_check_stage(e)
  br.log('Сохранено: ' .. tostring(br.storage_get('stage', 0)))
end
```

Сохранённый этап — не подтверждение, что состояние сервера осталось прежним. После переподключения перепроверяйте диалоги, позицию и другие реальные события. В полигоне хранилище виртуальное и очищается после запуска, диск не меняется. В отличие от боевого `--dry`, виртуальные операции полигона возвращают `status='simulated'`.

## Офлайн-полигон

Положите Lua-файл и JSON с событиями в `test_lua_scripts`, затем:

```sh
python -m logic.lua_sandbox my_script.lua --events my_events.json
```

Полигон использует виртуальное время. Именованные таймеры, их замена, отмена и виртуальное хранилище поддерживаются; повторяющийся таймер нужно завершать. Действует предел 200 событий на прогон. Полигон не подключается к игре, не подтверждает игровые ответы и не воспроизводит сам сервер: события нужно задавать в тестовом файле. Если получили `достигнут предел 200 событий`, проверьте бесконечный повтор.

## Диагностика

1. Проверьте версию загрузчика и доступность Lua 5.4, затем откройте лог нужного аккаунта.
2. Если `br.*` возвращает `false`, проверьте аргументы и предел действий. Для отложенных действий прочитайте `on_action_result`.
3. Если диалог не найден — запишите заголовок, стиль и очищенные строки без секретов. Не угадывайте `list_item`.
4. Если таймер не вызвался — проверьте имя `on_*`, ID, отмену, остановку сценария и предел очереди.
5. Если данные не сохраняются — убедитесь, что `br.armed=true`, известны ник и сервер и каталог `lua_data` доступен на запись. Не исправляйте повреждённый файл перезаписью без резервной копии.
6. Если в игре не происходит действие — `sent` не заменяет подтверждения сервера; нужны реальные события и логи для проверки механики.
