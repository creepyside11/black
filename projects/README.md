# Проекты

Один бот — несколько игровых проектов. Что где лежит:

| Что | Где |
|---|---|
| Реестр проектов (что вообще бывает) | `projects.py` в корне |
| Правки без кода: адреса API, файлы, лимиты, хендшейк | `projects.json` в корне (создаётся при первом переключении) |
| Профили id RPC/интерфейсов | эта папка, `<ключ>.profile.json` |
| Аккаунты проекта | `accounts.json` (BR), `accounts_arz.json` (Arizona RP) |
| Кэш списка серверов проекта | `.servers_cache.json`, `.servers_cache_arz.json` |
| Инструменты входа | `tools/project_handshake.py`, `tools/project_calibrate.py` |

## Переключение

- Telegram: главное меню -> `🌍 Проект`, или команда `/project arz`.
- Веб-панель: вкладка «Ещё» -> «Проект».
- Запуск: `python3 bot.py --project arz`, либо `BR_PROJECT=arz python3 bot.py`.

Активный проект сохраняется в `projects.json` и переживает перезапуск.

`projects.json` — источник правды для всего, что в нём есть: описание
проекта из файла перебивает то, что лежит в `projects.py`. Если ты правил
описание в коде и не видишь изменений — удали `projects.json` (файл
создастся заново, а активный проект сбросится на Black Russia).

## Что делает переключение

1. Сохраняет реестр текущего проекта на диск.
2. Останавливает всех запущенных ботов.
3. Меняет активный проект: список серверов, файл реестра, зона HTTP-пинга,
   лимит длины ника, профиль id.
4. Поднимает аккаунты нового проекта из его файла.

Ничего не удаляется: аккаунты каждого проекта лежат в своём файле и
возвращаются, когда проект включают обратно.

## Добавить третий проект

Дописать блок в `projects.json`:

```json
{
  "projects": {
    "rodina": {
      "title": "Rodina Mobile",
      "short": "ROD",
      "servers_api": [
        {"url": "https://api.arizona-five.com/launcher/servers",
         "path": "rodinaMobile"}
      ],
      "accounts_file": "accounts_rodina.json",
      "servers_cache_file": ".servers_cache_rodina.json",
      "http_host_suffix": "",
      "nickname_max": 20,
      "handshake": "raknet"
    }
  }
}
```

`path` — путь до массива серверов внутри ответа. Пустое значение значит
«ответ и есть массив» — так отдаёт Black Russia. `http_host_suffix` у
Arizona пустой намеренно: в её списке уже готовое имя сервера, и лишний
суффикс превратил бы Host в несуществующий домен.

## Вход в игру: `handshake`

Первым делом бот шлёт серверу свой пакет — и у проектов он разный.

| Значение | Что означает |
|---|---|
| `br` | три байта `04 42 52`, то есть id пакета `0x04` и маркер `b"BR"`; в ответ сервер шлёт `07 00`. Так устроен CRMP, то есть Black Russia |
| `raknet` | стандартный offline-обмен RakNet: `0x05` -> `0x06`, `0x07` -> `0x08`, `0x09` -> `0x10`. Так устроены SA-MP и его форки |

Про `b"BR"`: в коде метод называется `open_connection_request` и возвращает
два байта, поэтому легко решить, что в сокет уходит именно они. Уходит три —
id добавляет отправитель. Дамп исходящих у живого бота на это и показал:
`044252` наружу, `0700` в ответ. Проба с голым `b"BR"` молчит, и вердикт по
ней был бы неверным.

У Arizona в `projects.py` стоит `raknet`. Прежде чем запускать бота,
проверь, что сервер вообще отвечает на этот обмен:

```bash
python3 tools/project_handshake.py arz          # первый сервер из списка
python3 tools/project_handshake.py arz --server 3
python3 tools/project_handshake.py --host 185.169.134.3 --port 7777
```

Скрипт делает HTTP pre-ping, затем шлёт оба первых пакета и печатает
вердикт. Запускать его надо с той машины, где бот реально играет.

### Список серверов

У Arizona он теперь статический — 32 сервера, порт `7777`, номера `[1]`..`[32]`:

| Адрес | Номера |
|---|---|
| `185.169.134.3` .. `185.169.134.174` | 1-15, PHOENIX … PAYSON |
| `80.66.82.191` .. `80.66.82.199` | 16-32, GILBERT … SPACE |

API лончера больше не используется: он отдавал `mobile1/2/3` с портом
`5125`, а это не игровой порт — на нём UDP слушается, но хендшейка там нет.
Правь список в `projects.py` (`servers_static` у ключа `arz`).

### Что показал живой замер

| Проверка | Результат |
|---|---|
| Black Russia, `--server ORENBURG` | ответ `0700` за 52 мс, вход подтверждён калибровкой: 702 RPC, `connection_request_accepted`, `auth_key` |
| Arizona, сервера 1-32, порт 7777 | тишина на всё |

По Arizona подробно, чтобы не ходить по второму разу: ни один из 32 живых
серверов не ответил ни на `REQUEST_1` с версиями `1..16` (с magic и без, 18
и 1400 байт), ни на BR-формат `0x04 + b"BR"`, ни на перебор «id пакета +
маркер» (`AZ`, `AR`, `AA`, `AI`, `AM`, `MO`, `MP`, `SA`, `SN`, `AZRP`,
`ARIZONA`). Хосты при этом пингуются за 52-57 мс.

Про ICMP забыть: на этих серверах `port unreachable` не приходит **ни на
открытый порт, ни на закрытый** (7778 тоже молчит), так что судить по нему,
открыт ли порт, нельзя. Первый вывод «5125 открыт» был сделан именно так и
оказался неверным.

И главное: та же проба не получила ответа и от чужих SA-MP серверов с
онлайном 800-1200 (37.202.197.43, 51.79.37.125, 185.169.134.67), а
`185.169.134.67` — сосед Arizona по сети. Пока нет рабочего эталона, «сервер
молчит» ничего не доказывает: возможно, наш `REQUEST_1` собран не так.
Порядок такой: поднять локальный open.mp/SA-MP сервер, добиться ответа
`REPLY_1` от него, и только потом судить про Arizona.

Вывод честный: **вход на Arizona не работает**, пока не разобран формат её
первого пакета. Нужен дамп трафика живого клиента Arizona или разбор
`libsamp.so`. Как только формат будет известен, он станет третьим значением
`handshake` (например, `az`) с маркером в `projects.json`.

## Профиль id (`<ключ>.profile.json`)

Black Russia — не SA-MP из коробки: у неё своя нумерация RPC и
интерфейсов (`ShowDialog` = 347, ответ на диалог = 406 и так далее).
Arizona RP Mobile собрана из SA-MP-кода (`libsamp.so`), но серверные
скрипты у неё свои, поэтому часть id почти наверняка отличается.

Калибровка на живом сервере:

```bash
python3 tools/project_calibrate.py arz            # молча слушать
python3 tools/project_calibrate.py arz --login     # войти аккаунтом проекта
```

Скрипт подключается к серверу проекта, пишет входящие интерфейсы и RPC с
примерами тел пакетов и сохраняет отчёт в `.probe/calib_<ключ>.json`.
То, что отличается от Black Russia, вписывается в профиль:

```json
{
  "rpc": {"CLIENT_JOIN": 25, "INIT_GAME": 139},
  "interfaces": {"AUTH": 38},
  "packets": {"AUTH_KEY": 12},
  "raknet": {"version": 5, "magic": false}
}
```

Ключи `rpc`/`interfaces`/`packets` — имена из `samp/constants.py` (классы
`RPC`, `InterfaceID`, `PacketID`), значения — то, что показал замер.
`packets` нужен реже остальных: id самих пакетов у SA-MP-форков обычно те
же, а вот `AUTH_KEY` у Black Russia это 0x05, у SA-MP — 0x0C.

Секция `raknet` — версия протокола и наличие magic в первом пакете: по
умолчанию 5 и без magic, как у SA-MP 0.3.7. Если перебор в
`tools/project_handshake.py` показал другую версию, она вписывается сюда:
перебор на боевом канале недопустим — каждый вариант шлётся своим сокетом,
а входу нужен один.

Профиль применяется при запуске и при каждом переключении проекта, и
откатывается при возврате: пустой профиль Black Russia возвращает id к
исходным, а не оставляет чужие. Живой замер важнее догадок: неверный id —
это либо тишина, либо кик античитом.
